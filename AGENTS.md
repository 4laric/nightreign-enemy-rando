# AGENTS.md — guidance for AI coding agents

Practical orientation for working in this repo. Read `dev/ARCHITECTURE.md`
for the deep version; this file is the cheat sheet.

## What this is

A boss/enemy randomizer for **Elden Ring: Nightreign**. It shuffles which
enemies and Night Bosses occupy the placement slots across every map, driven
by a seed. It ships as a **self-contained me3 profile** (the mod loader is
me3). Vanilla game data is read from the user's own game archives at run
time — **no FromSoft data is redistributed**; `.gitignore` excludes all game
binaries, so missing `*.msb.dcx` / `*.emevd*` / `*.fmg` / `oo2core*.dll`
files are expected, NOT bugs.

## Entry points

- `oops_rando_gui.pyw` / `oops_rando_gui.py` — the tkinter GUI (~10.4k
  lines). `Launch.bat` is the Windows launcher.
- `oops_v3.py` — the engine + CLI (~10.8k lines). Its `__main__` re-execs
  itself with `PYTHONHASHSEED=0` — determinism is a contract; do not break
  the re-exec.
- The **release bundle layout differs from the repo tree**: the bundle has
  `randomize.pyw` / `randomize.sh` / `nightreign-enemy-rando.me3` /
  `nrando/` (the me3 package) / `_rando/` (the tool), all generated by
  `scripts/build_release.py` (`PACKAGE_SUBDIR='nrando'`). Don't assume repo
  paths in bundle-facing docs, or vice versa.

## Architecture

- `oops_v3.py` remains the **source of truth** for the engine. `engine/` is
  an incremental extraction from it: `state.py` (GateState snapshot),
  `runtime.py` (`apply_run_overrides`), `runctx.py` (per-run counters),
  `picker.py` (`pick_target_cp` gate cascade), `shuffler.py`
  (`shuffle_msb_v3`), `load_data.py` (startup loader), `pack_loaders/`
  (heritage / MMV rosters), plus spoilers, reservations, placement_budget,
  cap_groups, roster_resolve, rejection, import_planning/wizard,
  cmd_shuffle.
- Root support modules:
  - `oops_all_anyone.py` — MSB binary codec (the name is misleading).
  - `dcx.py` / `dcx_batch.py` — Oodle DCX pipeline: decompress → shuffle →
    recompress → healthbar pass (Step 4, via `healthbar_inplace`).
  - `data_archive.py` / `vanilla_source.py` / `nr_keys.py` / `aes128.py` —
    reading Nightreign's encrypted `.bhd`/`.bdt` archives (pure stdlib).
  - `er_source.py` / `er_keys.py` — same for Elden Ring (heritage imports).
  - `regulation_io.py` — regulation.bin codec:
    AES-256-CBC(DCX[ZSTD](BND4(*.param))); `Regulation.save()` is atomic
    (temp + `os.replace`) — keep it that way.
  - `regulation_rando.py` + `merchant_shop_fill.py` / `mob_drop_fill.py` /
    `npcparam_getsoul_fill.py` / `npcparam_reward_fill.py` / `drop_tiers.py`
    — the per-seed regulation passes (shop, drops, getSoul floors, reward
    lots, drop tiers).
  - `emevd_patch.py` — 14 registered EMEVD patches (`@register(...)`;
    `PATCHES` registry).
  - `me3_profile.py` / `me3_coherence.py` — .me3 generation and
    profile/package coherence checks.
  - `run_preflight.py` — pure pre-run validation + config→engine-kwargs
    mapping (extracted from the GUI post-v0.32; unit-tested, no tkinter).
  - `healthbar_inplace/` — pure-Python EMEVD binary parser/rewriter with
    its own test suite (`healthbar_inplace/tests/`).

## Data

`data/` holds the engine catalogs — see `data/README.md`. Most are generated
by `dev/` `emit_*` / `extract_*` / `build_*` tools: **regenerate with the
tool, never hand-edit** (staleness is test-locked for the override CSVs).
`data/NpcParam.csv` is a 9.5 MB vanilla dump — reference only; the live
bundled regulation differs from it on a meaningful fraction of rows, so
runtime passes read the live reg.

## Testing

- `pytest` (`pytest.ini`: `testpaths = tests healthbar_inplace/tests`).
  ~1930 tests; **fully green as of the v0.32 revival**.
- **Known environment issue:** full single-process runs can die with
  "Windows fatal exception: access violation" at random points
  (`ast.parse`/`json.load`). Run per-file or in chunks. Environmental, not
  a project bug — don't chase it.
- Determinism is a contract. Seed-lock fixtures in `tests/fixtures/`
  (`swap_plan_seed_lock.json`, `load_data_lock.json`, …) pin placement
  behavior — regenerate ONLY deliberately via the tests' sanctioned
  `--regenerate` path, and say so in the commit.
- Game-data-dependent tests must **skip, not fail**, when assets are absent
  (`skipif` gates).
- `tests/test_encoding_explicit.py` guards that all text reads pass
  `encoding="utf-8"` explicitly — always do so (Windows cp1252 default
  bites).

## Gotchas

- Engine `V3_*` globals are mutable module-level state. Tests must use
  conftest's `isolated_pool_snapshot` / `_save_v3_globals` fixtures — never
  hand-rolled save/restore.
- `data/mmv_imports.json` ships `_meta.enabled=false` intentionally (CTD
  risk without MMV installed).
- `patched_emevd/` binaries are DarkScript3 build outputs, absent from
  source checkouts (`.gitignore`; DarkScript3 is Windows/.NET-only).
  `healthbar_inplace/serialize.py` (append-only serializer) exists to
  eliminate that dependency but was not yet exercised — see
  `patched_emevd_js/README.md`.
- `dcx_batch.py` has a dormant, dir-guarded `rewired_msbs/` override path
  (v0.23.75): the directory doesn't ship, the `os.path.isdir` guard skips it
  silently. The comment pointing at `rewired_msbs/REWIRES.md` references a
  file that doesn't exist; the code path is live but inert.
- EMEVD recompilation needs DarkScript3 (Windows-only). The Oodle DLL is
  auto-detected from the user's Steam install.
- Windows assumptions throughout (`Launch.bat`, paths, Oodle DLL name).
- `dev/build_heritagae_pack.py` — the `heritagae` typo is historical and
  intentional as-is; don't rename the file.

## Version bookkeeping

On release, bump **all** of these together (they drifted once already):

1. `V3_ENGINE_VERSION` + `V3_ENGINE_FINGERPRINT` in `oops_v3.py` (~line 30)
2. `CHANGELOG.md` head entry
3. `PATCH_NOTES.md` head section
4. `README.md` "Current release"
5. GUI splash string in `oops_rando_gui.py` (`'vX.YZ — 4laric'`)

## Conventions (from CONTRIBUTING.md)

- Python 3.10+, pure-stdlib core; `cryptography` + `zstandard` are
  optional-but-default (regulation passes skip cleanly without them).
- Atomic file writes for user data: build in temp, rename/copy on success.
- Never ship FromSoft data.
- Everything seed-dependent must derive from the run seed (per-slot
  hashing, sorted pools).
